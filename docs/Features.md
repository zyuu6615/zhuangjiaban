# Touch_led 功能说明

STM32F103C8T6 触控/装甲灯板固件。核心作用：**本地开关或上位机 CAN 指令控制灯色 + 敲击检测与计数反馈**。

---

## 1. 一句话概括

一块挂在装甲板上的灯板：拨动本地开关或由上位机发 CAN 指令切换 **红/蓝/灭** 三种灯色；
被敲击时由振动传感器检测，**OLED 显示累计击打次数、蜂鸣器"滴"一声、并通过 CAN 上报给上位机**。

---

## 2. 对外功能

### 2.1 灯色控制（双控制源，对等）

| 控制源 | 操作 | 效果 |
|--------|------|------|
| 本地开关 | PB8 高 | 红灯 |
| 本地开关 | PB9 高 | 蓝灯 |
| 本地开关 | 都低 | 熄灭 |
| 本地开关 | 同时为高 | **红色优先**（代码里 if/else if 的顺序决定） |
| 上位机 | CAN `0x200` | 按 data[0] 设 0=灭 / 1=红 / 2=蓝 |

- 上电时开关**既不拨动也会先按当前档位刷新一次**（`switch_prev` 初值 -1 强制首次生效），
  所以默认（两路都低）就是**灭灯**。
- 灯带共 **16 颗 WS2812**（两级 × 8 颗），**16 颗始终同一颜色**。
- 颜色常量里还预置了 GREEN / YELLOW / CYAN / MAGENTA / WHITE，但当前逻辑只用到红、蓝、黑（灭）。

### 2.2 击打检测与反馈

| 环节 | 实现 |
|------|------|
| 传感 | PA10 上升沿中断（EXTI15_10，下拉输入），配振动/敲击传感器模块 |
| 计数 | 累计计数，**掉电不保存**（RAM 变量，无 Flash 存储） |
| 去抖 | 50 ms 窗口，窗口内的后续边沿不计入 |
| 视觉 | 灯带常亮队伍色（满亮度），每被击打一次**熄灭 160 ms 后自动恢复** |
| 听觉 | 蜂鸣器 PB5，每次计数变化响 **30 ms** |
| 显示 | OLED 显示 `Vibration` 与计数数值 |
| 上报 | 每次计数变化发一帧 CAN `0x100` |

**击打视觉反馈的设计**：不引入新颜色，用**亮度**区分状态 —— 平时满亮度常亮队伍色，
击打瞬间熄灭一下再恢复，形成"灭一拍"的打击感。灯色始终是队伍色（红队红 / 蓝队蓝），
色调统一，且无需改动 CAN 协议。亮度由 `LED_BASE_PCT` / `LED_FLASH_PCT` / `LED_FLASH_MS`
三个宏控制，想改成"变亮脉冲"只需把两个百分比对调。

**熄灭档下的击打反馈**：开关拨到"熄灭"时平时不亮，但被击打仍会用**最近一次确定的颜色**
亮 160 ms（用 `led_last_color` 记录），保证任何档位都能看到击打反馈；开机后从未选过颜色时按蓝色处理。

反馈的执行顺序为 **灯带 → 蜂鸣 → CAN 上报 → 刷 OLED**，把阻塞时间最长的 OLED 放最后，
保证视觉与听觉反馈都不被拖延。

**关于计数语义**：50 ms 去抖意味着计数上限约 **20 次/秒**，且一次物理敲击只算 1 次。
所以它是"**有效击打次数**"计数器，不是振动频率计。机械抖动引起的多次边沿会被合并。

**关于蜂鸣节奏**：`Buzzer_Beep()` 在上一声未结束时会被忽略（非阻塞状态机）。
连续快速敲击时，落在 30 ms 发声期内的那几次不会额外响 —— 这是刻意的设计，
避免连续敲击时蜂鸣器连成一片长音。30 ms 发声 < 50 ms 去抖窗口，保证下一拍到来前一定已关闭。

### 2.3 OLED 显示

SSD1306 128×64，I2C1（PB6/PB7，100 kHz），u8g2 全缓冲模式，字体 `ncenB14`。
两行内容：`Vibration` + 计数数值。

只在**计数变化时**刷新（不是每轮主循环都刷），避免无谓的 I2C 流量。

**屏幕未接也可正常工作**：I2C 单次超时 10 ms，连续失败 3 次后自动跳过刷屏，不再拖慢主循环。

## 3. CAN 通信接口

总线 500 kbps，标准帧。完整协议见 `docs/CAN_Protocol.md`。

| 方向 | ID | DLC | 内容 |
|------|----|-----|------|
| MCU → 上位机 | `0x100` | 5 | data[0]=灯状态(0灭/1红/2蓝) + data[1..4]=击打计数(uint32 小端) |
| 上位机 → MCU | `0x200` | ≥1 | data[0]=目标颜色(0/1/2)，其余字节忽略，>2 丢弃 |

上报触发时机（状态变化时才发，不周期广播）：
1. 灯色变化（本地或远程）；
2. 击打计数变化。

上位机发 `0x200` 后 MCU 会立即回一帧 `0x100`，可据此确认命令生效。

> 上电后若开关从未拨动过，`led_state` 仍为初值 -1，此时上报的 `data[0]` 是 `0xFF`（"未知"）。

## 4. 硬件资源分配

| 引脚 | 功能 | 外设 |
|------|------|------|
| PA0 | WS2812 数据 | TIM2_CH1 + DMA1_Ch5（PWM 归零码） |
| PA10 | 振动/敲击传感器 | EXTI10 上升沿 |
| PA11 / PA12 | CAN_RX / CAN_TX | CAN1 @ 500 kbps |
| PB5 | 蜂鸣器 | GPIO 推挽输出 |
| PB6 / PB7 | OLED SCL / SDA | I2C1 @ 100 kHz |
| PB8 / PB9 | 本地红/蓝开关 | GPIO 输入（下拉） |

时钟：**不依赖外部晶振**。启动时先探测 HSE，成功则 8 MHz × PLL9 = **72 MHz**；
若板上没焊晶振（本板实测如此）则回退 HSI/2 × PLL16 = **64 MHz**，再不行 48 MHz。
`WS2812_Init()` 会按实际 TIM2 时钟重算 ARR/CCR，所以三种主频下灯带时序都正确。
实际选了哪条分支记录在 `diag_clock_ok`（1=72M HSE / 3=64M HSI / 2=48M HSI）。

> ⚠️ 早期版本硬性要求 HSE，晶振缺失时 `HAL_RCC_OscConfig` 超时 → `Error_Handler()`
> 死循环 → 表现为"整机无反应、灯带完全不亮"。已修复。

## 5. 关键实现手法

**WS2812 波形生成**：不用软件延时打拍子，而是把每个 bit 预先换算成一个 PWM 比较值（CCR）
写进数组，再用 DMA 逐周期搬进 `TIM2->CCR1`。ARR 按实际主频现算（72 MHz → 89，64 MHz → 79），
保证位周期恰好 1.25 µs；0 码 ≈0.42 µs、1 码 ≈0.83 µs，帧尾 48 个 0 周期（60 µs）做复位锁存。
整帧仅 540 µs，由硬件保证时序，不受中断影响。

**本地/远程仲裁**：用独立的 `switch_prev`（只跟踪物理开关位置）做边沿比较，
而不是用 `led_state`（实际显示的颜色）。这样远程改了颜色后，只要开关没再动，
轮询就不会把颜色强行改回去 —— 实现"最后操作优先"。

**非阻塞蜂鸣**：`Buzzer_Beep()` 只负责拉低并记时间戳，
`Buzzer_Update()` 在主循环里检查是否到时关闭，全程不阻塞。

## 7. 开发与烧录

```powershell
cmake --preset Debug        # 或 Release
cmake --build --preset Debug

# 烧录（VSCode 任务 "OpenOCD: flash"，或手动）
openocd -f openocd.cfg -c "program build/Debug/Touch_led.elf verify reset exit"
```

VSCode 里直接按 F5 即可用 cortex-debug + OpenOCD 单步调试（`.vscode/launch.json` 已配好）。
调试时请用 **Debug 预设**（带 `-g3` 符号），Release 无调试符号。

硬件：ST-Link（SWD）+ OpenOCD，`openocd.cfg` 默认选 `interface/stlink.cfg` + `target/stm32f1x.cfg`。

**现场自检**：`tools/flash_verify.cfg` 一条命令完成"烧录 + 读回时钟/启动状态/灯带缓冲区/开关输入"，
不需要接示波器或万用表（诊断变量含义见 `applications/diag.h`）：

```powershell
openocd -f openocd.cfg -f tools/flash_verify.cfg
```

## 8. 已知限制 / 可扩展方向

| 项 | 说明 |
|----|------|
| 计数无清零 | `Vibration_Reset()` 已实现但从未被调用，CAN 协议也没有清零命令 |
| 无固件版本上报 | 协议里没有版本字段，现场不好确认烧的是哪一版 |
| 计数掉电丢失 | 存在 RAM，断电归零 |
| 灯色只有 3 种 | 16 颗灯始终同色；`WS2812_SetPixel` 已具备逐颗控制能力，可做流水/进度条效果 |
| CAN 过滤器全通过 | 目前接收所有 ID 再软件筛选；接入高负载总线时建议收窄到 `0x200` |
| 无看门狗 | 未启用 IWDG |
| CAN bus-off 无恢复 | `AutoBusOff` 关闭且无错误回调，总线异常后会失联到断电 |

> 详细问题分析与修复建议见 `docs/Code_Review.md`。
